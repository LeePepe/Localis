## 1. E1 — 后台续跑：现有契约做不到，必须改

### 1.1 矛盾在哪

**产品承诺**（用户已确认）：切到后台，生成在主机上继续跑，回来时同步。

**现契约 §3.2 原文**：

> 关闭 HTTP 连接即取消。**bridge 收到断连后必须终止对应的后端进程/请求。**

**iOS 事实**：App 进入后台后，系统会挂起进程、断掉 URLSession 连接。

三者合起来：**切后台 = 断连 = bridge 杀掉生成**。承诺**在现有协议下无法实现**——
这不是「iOS 侧多写点代码」能补的，是契约把它禁掉了。

原 spec 的 FR-019（「被系统中断的流标 `interrupted` 并可重试」）正是**建立在这个前提上**的：
它假设「中断 = 内容丢了，只能重来」。**新承诺要求的是「中断 = 连接断了，但活还在干」**——
两种模型截然不同，不是同一件事的不同措辞。

### 1.2 关键洞察：**不需要**让 iOS 在后台保持连接

一个容易走偏的思路是「申请后台执行时间、保活连接」——那条路会撞上 iOS 的后台时长限制，
且注定不稳。

**正确的形状是：让连接变得可抛弃。**

- 生成的**权威**在 bridge 侧：它继续跑、把输出**缓冲**起来。
- 客户端断了就断了，**不申请任何后台时间**。
- 回前台时**重连并从游标续取**，把缺的那段补回来。

如此，iOS 的后台限制**完全不参与**这个问题——它只影响「你什么时候回来取」，不影响「活有没有干完」。
这也顺带解决了「杀 App 重开」「地铁断网」等场景，它们与「切后台」在协议上是同一件事。

### 1.3 协议改动（三件）

**(1) 断连 ≠ 取消。** §3.2 语义反转：断连时 bridge **MUST NOT** 终止后端；
必须继续生成并缓冲输出，等待客户端在保留窗口内回来续取。

**(2) 显式取消端点。** 断连不再表示取消，「停止」按钮就需要一个真的说法：
`POST /v1/turns/{turn_id}/cancel`。这是**新增能力**，不是可选礼貌——
没有它，用户点「停止」将无法真正停下主机上的活。

**(3) 续取（resume）+ 游标。** 每个 turn 有 `turn_id`；每个 SSE 事件有**单调递增** `seq`。
重连时带 `x-localis-resume-from: <last seq>`，bridge 从该点之后重放。
`seq` 同时用于**去重**——重放边界上收到重复帧时按 `seq` 丢弃，这是「无缺字无重复」
（SC-003）在断连场景下的保证。

### 1.4 向后兼容：**能力协商，不 bump 版本**

老 bridge 断连即杀。若客户端一厢情愿地假设「活还在」，会在老 bridge 上表现为**静默丢结果**——
比现在还糟。

故：**bridge 在 `/v1/models` 的 host 级 `x_localis` 里声明 `resumable_turns`**（见 §1.6）。

| host 是否声明 `resumable_turns` | 客户端行为 |
|---|---|
| **是** | 断连不取消；回来续取；消息状态走 `detached → complete` |
| **否**（或老 bridge） | **退回现有语义**：断连即取消，标 `interrupted` 可重试（FR-019 原样保留） |

因此**协议版本仍为 `1`**：新端点是加法，语义反转由能力位门控，老 bridge 照常工作。
这与宪法 IV「能力是数据，不是代码分支」同源——**且它天然是逐 host 的**
（Amendment A）：一台主机支持续跑、另一台不支持，是合法状态。

### 1.5 消息状态：`interrupted` 不够用了

现状态机把「连接断了」和「内容丢了」混为一谈。拆开：

| 状态 | 含义 | 用户看到 |
|---|---|---|
| `streaming` | 正在收 | 逐字出现 |
| **[C] `detached`** | **连接断了，但主机还在生成** | 「仍在 <主机> 上运行」+ 可取消；**不提示重试** |
| `interrupted` | 内容确实丢了（不支持续跑，或超出保留窗口） | 「已中断」+ **重试** |
| `complete` | 收完了 | 正常 |
| `failed` | 出错 | 人话错误 |

**关键**：`detached` **不得**向用户提示「重试」——活还在干，重试会**跑出第二份**。
把二者混同正是当前设计最危险的地方：用户看到「已中断」→ 点重试 → 主机上同时跑两个任务。

### 1.6 保留窗口与边界（必须写死，否则是内存泄漏）

bridge 缓冲不能无限。契约规定 bridge **MUST** 声明并执行边界：

- **保留窗口**：turn 结束后至少保留 `retention_seconds`（建议 ≥ 300s）供续取。
- **缓冲上限**：超出上限时 bridge **MUST** 截断并在续取时明确告知
  （客户端据此把该消息标 `interrupted` 而非 `complete`——**宁可说丢了，不可假装完整**）。
- **孤儿 turn**：客户端再没回来，窗口过期即回收。

这些值由 host 在 `/v1/models` 的 host 级 `x_localis` 中声明，客户端**不得硬编码**（宪法 §无硬编码）。

### 1.7 与多主机的交互

- 续取是**逐主机**的：A 支持、B 不支持是合法状态，UI 需按主机呈现不同的「停止/重试」语义。
- 一台主机上有 `detached` 的 turn，**不得**影响其它主机（Amendment A FR-034 已覆盖）。
- 重连恢复时，客户端 **MUST** 按 `(hostID, sessionID, turn_id)` 归位续取的内容。

## 2. E2 — 遥测/活动接缝

用户原话：**「如果有可以用的就尽量展示，或者保留之后接入的可能」**——
**能拿到的展示，拿不到的留口子**。

### 2.1 原则：复用既有机制，不发明第二套

宪法 IV 已经给了答案：**能力是开放数据，未知字段忽略**。遥测**完全套用**这一套，
不新增任何并行机制：

- 新遥测字段 = bridge 多发一个 key，**iOS 零改动、零发版**（与「新增第 6 个后端」同构）。
- iOS **MUST** 忽略未知字段而非丢弃整帧（FR-010 既有规则）。
- **UI MUST 按「字段存在与否」渲染，MUST NOT 按后端名字判断**——某后端不报 token 数，
  就是不显示那一项，不是写个 `if backend == "claude"`。

### 2.2 v1 就能拿到的（列为契约，designer 可以放心画）

**来源**：designer 在 `design/prototype/README.md` 的「确定 vs seam」标注。逐条落成契约：

| 元素 | 状态 | 契约落点 |
|---|---|---|
| **当前工具调用 + 参数** | **Certain** | **需要新契约**：§3.1(a) 的 `x-localis-tool-call` 加 `phase: start/end` + `call_id` 生命周期 |
| **工具调用历史 / 时长 / 退出状态** | **Certain** | 同一事件流，**客户端累积两个帧即可**，无需新端点 |
| **模型名** | **Certain** | `/v1/models` 的 backend descriptor 已隐含 |
| **workspace 路径** | **Certain** | 已有 `x-localis-workspace`。**远程比本地更重要**（「这东西能碰到什么」）；**MUST 由 bridge 缩写**（`~/dev/foo`，宪法 I） |
| **已用时间 / 消息数** | **Certain** | **客户端可推导**，不需要任何新 bridge 能力 |
| **后台期间的会话结局** | **Certain** | **需要新契约**：§3.1(d) 的 `x-localis-turn-end`（completed / failed / cancelled） |
| **token usage** | **Certain** | §3.4(a)：`usage` 为 SHOULD；**有则真实渲染，无则整块不出现**（**不留占位空槽**） |
| **cost（金额）** | **SEAM** | **v1 不做，界面上不存在该元素**；日后由 bridge 算好显示值经开放信封下发，iOS 零发版 |

**新增的两个事件是本次契约的实质增量**（其余「Certain」项要么已在契约里、要么客户端自推）：

1. **工具调用生命周期**（`phase` + `call_id`）。**`call_id` 是必需的**——并发工具调用会**交错**，
   没有关联键就无法把 `end` 配回它的 `start`。这是最容易被漏掉的设计点。
2. **`x-localis-turn-end`**。这是**后台续跑的闭环**：designer 画的三种回归结局
   （已完成 / 仍在流 / 期间失败）分别对应「续取后立刻收到 `turn-end: completed`」
   「继续收到 delta」「收到 `turn-end: failed` + 进度」。**客户端无需猜测。**
   失败必须**可行动**：带 `failed_at_ms` + `tool_calls_completed`，
   使 UI 能说「跑了 8 分钟、完成 3 次工具调用后失败」而非干巴巴「出错了」。

### 2.3 tokens 与 cost：**拆开**（一次自我更正）

**曾经写错的版本**：把 tokens 与 cost 捆成同一个 SEAM，要求「槽位存在，缺失时显示『不可用』」。
**已作废。** 更正由 designer 提出并采纳，因为它与本修正案**自己的** §2.4 规则相矛盾：

> §2.4 早就规定「**按字段存在与否渲染**」，而「永远显示『不可用』的空槽」正是一个
> **为可能永不到来的数据留下的占位空洞**——它暗示数据即将到来，**本身就是一种误导**。
> 两条规则不能同时成立；**存在性渲染那条是对的**。

**更正后**：

| 项 | 结论 |
|---|---|
| **token usage** | **Certain 数据**。bridge SHOULD 提供；客户端**有则真实渲染，无则整块不出现**。不得显示 `0`、不得编造、**不得留占位空槽** |
| **cost（金额）** | **真正的 seam**。v1 不做，且**界面上不留任何位置**。日后由 bridge 算好显示值经开放信封（§2.4）下发——**加它不需要 iOS 发版** |

**为什么二者性质不同**：`usage` 是 bridge **已经能给**的真实测量值；
cost 是**端上算不出**的（定价随模型与套餐变化，算完立刻过期）。
把它们捆在一起判断，是本修正案初稿的错误。



### 2.4 开放遥测信封（**这就是「留口子」本身**）

新增一个**故意开放**的事件：`event: x-localis-telemetry`，载荷是自由 key-value。
客户端把**认识的**键渲染成对应控件，**不认识的**键**忽略**（也可在调试构建里原样列出）。

意义：日后想加「队列深度」「GPU 温度」「剩余配额」……**bridge 多发一个键即可，iOS 零改动**。
这是把宪法 IV 的红利从「后端」扩展到「遥测」。

> **隐私边界（宪法 I）**：遥测 **MUST NOT** 携带对话正文、绝对路径、token。
> 工作目录若要展示 **MUST** 由 bridge 侧缩写（`~/dev/foo`），
> 且客户端 **MUST NOT** 把遥测写日志。

### 2.5 designer 交接

designer 正在标注「确定 vs 推测」的 UI 元素。规则：
**§2.2 表中的四项是确定的**（可以画实心）；其余一律经 §2.4 的开放信封进来，
按「有就显示、没有就整块不出现」设计——**不要为可能不存在的数据留占位空洞**。

## 3. E3 — iPad 是对等设备

Amendment A 写的是「iPad 纳入范围」，措辞上留了「是不是次要设备」的解释空间。**收紧**：

**iPad 与 iPhone 功能完全对等**——多主机管理、配对、多会话并发、`/` skill 插入、
后台续跑、遥测展示，**一件不少**。iPad **不是**「只读伴侣」。

验收含义：**US1–US6 的全部验收场景在 iPad 上同样必须成立**，
而不只是 Amendment A 已列的 US1/US3 smoke（SC-013 相应扩展）。

## 4. E4 — 回答 designer

### 4.1 skill 离线：**采纳你的偏好（缓存 + 标记过期 + 允许插入）**，但只在内存

你的论证成立：**skill 现在就是一段文本，离线插入它零成本；选择器因为机器睡了就空掉，
比帮倒忙还糟。** 采纳：

- 缓存有货 → **照常显示，标注「可能已过期」，插入照常允许**。
- **仅在本次进程内从未拉到过**该主机的目录 → 空态（「连上 <主机> 后才能加载 skill」）。

**为什么不落库**（v1 的取舍，明确记录）：落库能让「重启 App 后离线仍有 skill」成立，
但要引入一张表 + 一次迁移 + 一条隐私面（模板可能含路径，宪法 I）。
覆盖的增量场景很窄——**只有「冷启动 + 该主机不可达」这一格**。v1 不做。
日后要做是**纯增量**（加一层持久化，无协议、无模型变更）。这是留的口子，不是遗漏。

### 4.2 你要的字段

| 字段 | 结论 |
|---|---|
| **`lastSeenAt`** | ✅ **加**。你的理由成立——「6 分钟前」与「3 天前」是两种不同处境。它是**派生的运行时状态，不是持久化字段**（与 `reachability`/`latencyMs` 同类）。 |
| **`kind: .mac/.nas/.vps/.other`** | ✅ **已加**（Amendment B 就并进实体表了）。**仅影响图标与文案**，不参与任何逻辑分支。 |

### 4.3 你明确不要的，我也不加

- **主机颜色** — 不加。你的理由（色相已经承载 backend 身份，再给主机一套会撞车）比我原来的
  提议更有道理。已从待办里划掉。
- **`isDefault` / 默认主机** — 不加。同意「UI 需要的是**上次用过的主机**，那是会话派生值」。
  一个能和「你实际上次用的」不一致的默认值，是看不见的 bug。

### 4.4 你提的那条，我写进 spec 了

> 「不可达会话的输入框必须**可见地禁用并说明原因**，而不是默默收下注定失败的文本。」

已成为 FR-053。这是对的——静默接受一段发不出去的文本，是把失败推迟到用户按下发送之后。

## 5. 合宪性

| 原则 | 结论 |
|---|---|
| **I. 密钥零上设备** | ✅ 遥测新增了一个**泄漏面**（路径、正文），已由 §2.4 显式封堵：不得带正文/绝对路径/token，不得写日志。续取游标 `turn_id`/`seq` 是元数据，非敏感。 |
| **II. Swift 6 并发** | ✅ 续取让流的生命周期**超出前台**，但表达手段不变（actor 持有 turn 状态）。**新风险**：重连时新旧两条流并存 → 必须按 `seq` 去重，禁止两个 task 同写一条消息。 |
| **III. SPM 分层** | ✅ 不新增包。续取属 TransportKit（协议）+ ChatService（编排）；遥测是 LocalisModels 的一个开放值类型。 |
| **IV. 单一协议** | ✅ **核心合规点**：续跑与遥测**都**用能力位/开放字段表达，不是代码分支。新增遥测字段 = iOS 零改动，与「新增第 6 个后端」完全同构。 |
| **V. TLS + 配对** | ✅ 续取走同一套鉴权与 pinning。**新面**：`turn_id` 可被猜测则可能被他人续取他人的流 → 契约要求 `turn_id` **不可预测**且续取**必须**校验 bearer token 属于同一设备。 |
| **VI. 不可变** | ✅ 续取内容仍是「追加产生新快照」。 |
| **VII. 范围克制** | ✅ 不新增 target。**注意**：这**不是**在做 APNs——Out of Scope 里的「APNs 后台完成通知」仍然不做。续跑是**回前台时同步**，不是推送唤醒。二者别混。 |

**无违宪项。** 但 E1 是本项目**第一次真正的协议语义变更**（前两次修正案都只是加字段），
故用能力位门控 + 老 bridge 优雅降级，而非硬 bump。
